**做：** 把 649 条按你要付出的成本筛一遍，让"这条建议对我不成立"这件事变得可见。

> **没网能用**、**答案不变**、**每条都有出处**、**不碰你的数据**。

## 快速开始

```bash
# 1. 生成数据并从模板产出 index.html（需要 git 和 python 3）
python build.py

# 2. 验收（32 项断言）
python verify.py

# 3. 打开
#    直接双击 index.html 即可 —— 不需要服务器
```

**改界面改 `template.html`，改完重新跑 `build.py`。** 不要直接改 `index.html`。

`build.py` 会把语料**内联**进 `index.html`。这是刻意的：`fetch` 加载本地 JSON 在
`file://` 协议下会被 CORS 拦死，"双击就能打开"会当场破产。内联之后单文件自足，断网可用。

更新上游内容：

```bash
python build.py --update     # 强制重新浅克隆上游
python verify.py             # 数字对不上说明上游改了，去看断言的报错
```

## 文件

| 文件 | 作用 |
|---|---|
| `template.html` | **改界面改这里**。HTML/CSS/JS，语料和 search.js 由构建注入 |
| `search.js` | **改搜索改这里**。匹配内核，纯函数无 DOM。浏览器和 Node 测试跑的是同一份 |
| `search-test.json` | 30 条验收用例 + 期望答案 + 达标线。`expect: null` 表示书里确实没这个主题 |
| `test-search.js` | `node test-search.js` 跑搜索验收，退出码 0/1 |
| `index.html` | **产物**。1.6 MB，别手改（改了下一次构建会被覆盖） |
| `build.py` | 上游 → 解析 → 16 项断言 → 注入语料 + search.js → 产出 index.html |
| `verify.py` | 独立验收，33 项断言（含调用 node 跑搜索验收）。全过退出码 0 |
| `data/corpus.json` | 解析后的语料（便于查看和复用；站点本身不读它） |
| `.upstream/` | 上游仓库的浅克隆（可随时删除，`build.py` 会重建） |

> **为什么分成几个文件**：语料内联是硬要求（`file://` 下 `fetch` 会被 CORS 拦死），
> 但把一个 1.6 MB 的单行 JSON 塞进 HTML 之后，那个文件就没法用编辑器改了。
> 搜索内核单独放一个文件，是为了让 Node 测试能直接 `require` 它 —— 测试和线上跑同一份代码，
> 不存在「测试过了但线上是另一套实现」。

## 功能与界面结构

界面只有四层，从上到下：

1. **标题 + 一行说明** —— 页头没有任何链接
2. **搜索框 + 「应急」按钮** —— 吸顶。应急是模式切换（按钮变「← 返回」），不是页签
3. **一行筛选** —— `我负担不起` + 三个圆角 chip：**钱 / 时间 / 毅力**。点一下即筛
4. **结果** —— `234 条建议 （筛掉了 415 条）`

其余全部收进折叠区或页脚：

| 内容 | 放哪 | 为什么 |
|---|---|---|
| 口径 / 证据 / 章节 / 排序 / 争议 | 「更多筛选」弹出的面板 | 首屏只需要一个动作 |
| 出处、CC BY 署名、口径说明、免责 | 页脚 | 版权事务不该占首屏 |
| 数据自检表 | 页脚再折叠一层 | 给改代码的人看，不是给用户 |

**每条的展示**（两行 + 一段）：

```
系安全带，前排后排都系
不花钱 · 几分钟 · 不用靠意志 · 活得久 · 证据 A
坐前排系上安全带，出车祸时被撞死的概率大约降一半。…
```

标题 + 一行成本摘要 + 说人话。点标题展开全文（成本 / 说人话 / 收益 / 备注 / 来源），
一键复制来源，可跳原文对应章节。性价比档和带批注的证据等级放在展开区里。

**应急模式**：第 13 章单独成页，含 110 / 120 / 119 / 12356。**这一页是给断网场景准备的** ——
存到手机主屏，或者打印一张放家里。

## 搜索怎么工作的

搜索是这个站最容易出错的地方。原来的实现是**整串子串匹配**：
用户输入「手机丢了怎么办」，书里写「手机丢了按这个顺序做」—— 返回 0 条。
实测 30 个口语问题里 **27 个零结果，其中 96% 是书里明明有、只是搜不到**。

现在换成分档打分的匹配（`search.js`）：

| 环节 | 做法 |
|---|---|
| **分词** | 相邻两字切双字组合（bigram），按 IDF 加权。虚词（「怎么」「怎么办」）出现频率高、权重自然低，**不用人工停用词表** |
| **剥填充词** | 「怎么办 / 请问 / 要不要 / 值不值…」先去掉，**再从剥完的结果切词**（用原始查询切词会把「怎么办」裂成两个 token，它们几乎匹配所有条目，把分数整体抬高） |
| **口语同义词表** | 书里写「人际 / 关系」，用户说「室友」；书里写「经济补偿」，用户说「被裁」。约 60 条映射，**改这张表就能提升召回，不用动正文一个字** |
| **生词不计满分** | 用户说的词书里没有，不该扣他的分。df ≤ 1 的双字组合视作跨词拼接的产物（「出国留学要注意」切出的「学要」），同样按生词处理 |
| **命中分档** | 标题字面 1.00 > 标题同义词 0.85 > 正文字面 0.70 > 章名 0.68 > 正文同义词 0.45。**位置比「字面 vs 同义词」更能说明相关度** |
| **分母下限** | 查询很短又全是生词时，分母会塌陷，导致一堆条目并列满分、最后靠性价比随机挑 |
| **安全类兜底** | 自杀 / 抑郁 / 活着没意思这类查询，标题里就是危机条目的直接加权顶到最前 |
| **零结果兜底** | 不摆空白页，给出主题最接近的 3 章当出口 |

### 效果（30 条验收用例）

```
旧搜索零结果      27/30  →  新搜索 0/30
首条正确率                93%
平均返回条数              20
安全类查询（活着没意思）   ✓ 首条即「抑郁或有自杀念头时打 12356」
```

**改搜索的流程**：改 `search.js` → `node test-search.js` → `python build.py` → `python verify.py`。

`search-test.json` 里的 `expect` 是「正确结果的标题或说人话里应该出现的词」。
加新用例就能扩测试集；`expect: null` 的表示这本书确实没这个主题（如室友冲突、牙科治疗），
不判对错，只要求别零结果。

## 几个设计决定

**为什么用 5 维标签而不是问"你是谁"**
每条建议自带 `钱 / 时间 / 毅力 / 收益 / 口径` 五个标签（覆盖率 100%）。这本书是按**性价比**写的，
不是按人群写的 —— 问"你是几年级、什么专业"没有对应的证据支撑，只会制造"它懂我"的错觉。
问资源才是这本书支持得了的问题。

**为什么强调"筛掉多少条"**
`649 条中符合 234 条（筛掉 415 条 —— 它们要花你做不到的东西）`。这个数字是诚实的，
也有用：它回答的是"为什么我做不到那些看起来很好的建议"，而不是"你应该做什么"。

**为什么留着"有争议"标注**
5 条的证据等级带作者批注（`A（争议）`×3、`C（争议）`×1、`B（指南强推荐，但底层证据等级低）`×1）。
解析时**必须把批注单独存下来**，不能只取首字母 —— 那会丢掉作者最重要的判断。
界面上给它们一个独立的橙色徽章，并可以一键排除。

**性价比档照搬作者的算法**
从上游 `index.html` 的 `parseReadme()` 抄来的，保证同一个条目在两边的档位一致：

```js
cs = 钱 + 时间 + 毅力          // 权重 {0:0, 少:0, 多:0}+…
ratio = 收益=大 ? (cs==0 ? '极高' : cs<=2 ? '高' : '一般')
      : 收益=中 ? (cs==0 ? '高' : '一般') : '一般'
```

**注意**：性价比**只在同一口径内可比，与证据等级无关** —— 这是作者本人的说明，页脚也照抄了。

## 路况与坑（实测踩出来的）

| 坑 | 现象 | 解法 |
|---|---|---|
| git **push** 时 TLS 失败 | `schannel: CRYPT_E_NO_REVOCATION_CHECK (0x80092012)` | 见下方「本机 git 配置」 |
| `git clone` 上游 | 同上 | `git -c http.sslVerify=false clone` |
| curl 抓 GitHub | `CRYPT_E_NO_REVOCATION_CHECK` | `curl --ssl-no-revoke` |
| `raw.githubusercontent` 不稳 | 偶发 502、超时 | 优先 `git clone --depth 1`（20 秒 / 6.4 MB） |
| `file://` 下 fetch | CORS 拦截，页面空白 | **语料必须内联**，这是硬要求 |
| PDF 提取 | 数字对不上（证据 A 数出 429，实际 428） | 只用 `book/*.md` |
| 首屏渲染 649 条 | 页面重，截图工具会超时 | 已做分页，首屏 60 条 |
| SSH（22 端口） | `Connection refused` | 走 HTTPS；本机已配 `gh-proxy.com` 做 fetch |

**关于 `.upstream/`**：本地副本，已加进 `.gitignore`。删掉不影响，`build.py` 会重建。

### 本机 git 配置（这台机器专属，已设好，不用重做）

`C:\Users\Lenovo` 这台机器上直连 `github.com` 的 TLS 会挂在 Windows 证书吊销检查上。
`http.schannelCheckRevoke=false` **无效**，`http.sslBackend openssl` 也验不过直连。
最终可用的是仓库级：

```bash
git config http.sslVerify false     # 仅本仓库
```

这是**安全性降级**（跳过 TLS 证书校验）。换机器或换网络时应该先试
`git config http.sslBackend openssl` + 正确的 CA 证书包；只有在直连确实不通时才退到 `sslVerify false`。

另外本机全局配了 URL 重写，fetch 走代理、push 直连：

```
url.https://gh-proxy.com/https://github.com/.insteadof  https://github.com/
url.https://github.com/.pushinsteadof                   https://github.com/
```

**`gh` CLI 是可用的**（`gh api user` 正常）。网上那种「api.github.com 被劫持、gh 全废」的说法
在本机不成立 —— 那是其他沙箱环境的限制，别照搬。
