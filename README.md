## 它做什么 / 不做什么

**做：** 把 649 条按你要付出的成本筛一遍，让"这条建议对我不成立"这件事变得可见。

**不做：** 不生成建议、不替你决定、不做开放问答、不收集任何数据。

> 通用 AI 会给你一个答案。这个站给你一个**出处**。要开放问答去问 AI；这个站的价值在于
> **没网能用**、**答案不变**、**每条都有出处**、**不碰你的数据**。

## 快速开始

```bash
# 1. 生成数据并从模板产出 index.html（需要 git 和 python 3）
python build.py

# 2. 验收（33 项断言 + 55 条搜索用例）
python verify.py

# 3. 打开
#    直接双击 index.html 即可 —— 不需要服务器
```

**改界面改 `template.html`，改完重新跑 `build.py`。** 不要直接改 `index.html`。

`build.py` 会把语料**内联**进 `index.html`。这是刻意的：`fetch` 加载本地 JSON 在
`file://` 协议下会被 CORS 拦死，"双击就能打开"会当场破产。内联之后单文件自足，断网可用。

更新上游内容：

```bash
python build.py --update     # 强制重新浅克隆上游
python verify.py             # 数字对不上说明上游改了，去看断言的报错
```

## 文件

| 文件 | 作用 |
|---|---|
| `template.html` | **改界面改这里**。HTML/CSS/JS，语料和 search.js 由构建注入 |
| `search.js` | **改搜索改这里**。匹配内核，纯函数无 DOM。浏览器和 Node 测试跑的是同一份 |
| `search-test.json` | **验收用例 + 达标线**。55 条分三组：`cases` 短查询 / `hard` 长句单字英文 / `stability` 同义改写；`must_not_be_zero` 列输入类型必须支持的查询。每个临界值都附了理由 |
| `test-search.js` | `node test-search.js` 跑搜索验收，八项指标，退出码 0/1 |
| `verify-live.js` | `node verify-live.js <线上html>` **线下验线上**：抽出页面里内联的 search.js 和语料，跑同一套用例，并核对语料与 `data/corpus.json` 一致 |
| `index.html` | **产物**。1.6 MB，别手改（改了下一次构建会被覆盖） |
| `build.py` | 上游 → 解析 → 16 项断言 → 注入语料 + search.js → 产出 index.html |
| `verify.py` | 独立验收，33 项断言（含调用 node 跑搜索验收）。全过退出码 0 |
| `data/corpus.json` | 解析后的语料（便于查看和复用；站点本身不读它） |
| `.upstream/` | 上游仓库的浅克隆（可随时删除，`build.py` 会重建） |

> **为什么分成几个文件**：语料内联是硬要求（`file://` 下 `fetch` 会被 CORS 拦死），
> 但把一个 1.6 MB 的单行 JSON 塞进 HTML 之后，那个文件就没法用编辑器改了。
> 搜索内核单独放一个文件，是为了让 Node 测试能直接 `require` 它 —— 测试和线上跑同一份代码，
> 不存在「测试过了但线上是另一套实现」。

## 功能与界面结构

界面只有四层，从上到下：

1. **标题 + 一行说明** —— 页头没有任何链接
2. **搜索框 + 「应急」按钮** —— 吸顶。应急是模式切换（按钮变「← 返回」），不是页签
3. **一行筛选** —— `我负担不起` + 三个圆角 chip：**钱 / 时间 / 毅力**。点一下即筛
4. **结果** —— `234 条建议 （筛掉了 415 条）`

其余全部收进折叠区或页脚：

| 内容 | 放哪 | 为什么 |
|---|---|---|
| 口径 / 证据 / 章节 / 排序 / 争议 | 「更多筛选」弹出的面板 | 首屏只需要一个动作 |
| 出处、CC BY 署名、口径说明、免责 | 页脚 | 版权事务不该占首屏 |
| 数据自检表 | 页脚再折叠一层 | 给改代码的人看，不是给用户 |

**每条的展示**（两行 + 一段）：

```
系安全带，前排后排都系
不花钱 · 几分钟 · 不用靠意志 · 活得久 · 证据 A
坐前排系上安全带，出车祸时被撞死的概率大约降一半。…
```

标题 + 一行成本摘要 + 说人话。点标题展开全文（成本 / 说人话 / 收益 / 备注 / 来源），
一键复制来源，可跳原文对应章节。性价比档和带批注的证据等级放在展开区里。

**应急模式**：第 13 章单独成页，含 110 / 120 / 119 / 12356。**这一页是给断网场景准备的** ——
存到手机主屏，或者打印一张放家里。

## 搜索怎么工作的

搜索是这个站最容易出错的地方。原来的实现是**整串子串匹配**：
用户输入「手机丢了怎么办」，书里写「手机丢了按这个顺序做」—— 返回 0 条。

### 先记一件事：这个搜索被自己骗过一次

第一版换成分档打分后，验收是「30 条用例零结果 0/30、首条正确率 93%」。
**这个数字是过拟合出来的** —— 那 30 条全是我自己挑的短查询，而且用词都贴近书里的
标题写法。真人根本不这么打字。

后来找了一个不知道这段推理过程的独立评审去攻击它，实测复现出这些问题：

| 查询（真人的打字方式） | 旧实现 | 问题 |
|---|---|---|
| 我跟房东签了合同但他现在不退我押金我该怎么办 | **0 条** | 长句全灭 |
| 我上个月被裁员了现在没有收入还要还房贷 | **0 条** | 长句全灭 |
| 死 | **0 条** | 单字查询恒为 0，**安全兜底完全失效** |
| 不想戒烟 | 命中「别自己硬戒」 | 那是讲酒精戒断的，语义相反 |
| 被裁 / 被裁了 | 3 条 / 84 条 | 加一个字结果翻 28 倍 |
| 老板把我炒了 | 30 条，首条讲卖假货 | 口语词不在表里就退化成字面噪声 |

**根因不是参数没调好，是评分公式本身有结构性缺陷。** 逐条记在下面，
免得以后有人（包括我自己）又把它改回去。

### 评分模型（当前）

```
取 token   = 查询里【已知】token 按 IDF 降序取前 3 个
分母 denom = 这 3 个 token 的 IDF 之和
分子 got   = 这 3 个 token 各自命中时的「IDF × 分档系数」之和
分数 sc    = got / denom        ← 恒在 0~1
```

| 环节 | 做法 | 为什么 |
|---|---|---|
| **分词** | 相邻两字切 bigram，按 IDF 加权 | 虚词出现频率高、权重自然低，不用人工停用词表 |
| **剥填充词** | 「怎么办 / 要不要 / 值不值」等**先剥再切词**；另有一组连词/副词/时间词（而且、但是、因为、现在、一直、上周…） | 用原始查询切词会把「怎么办」裂成两个几乎匹配所有条目的 token。连词本身是「真词」，过滤器拦不住，却会占掉分母 —— 实测「被裁了而且没钱交房租」的分母里「而且」排第二。剥掉它们还顺带把被连词打断的真词接回来 |
| **假词滤除** | 一个 bigram 算「真词」需要**两个条件同时成立**：① 绑定率 ≥ 0.10（该 bigram 的条目数接近它那个更罕见单字的条目数）② 出现在某条标题里 | 「我上个月被裁员了」会切出「月被」—— 前一个词的尾字 + 后一个词的首字。它在 2 条条目里碰巧出现过，就拿到最高 IDF 挤进分母，把「被裁」压到阈值以下。**单选一个判据都不够**：「被裁」(.115，真) 和「纪大」(.182，假) 区间交叉，只看①分不开；而「个月」也出现在标题里（「不满六个月按半个月」），只看②又太宽 |
| **OOV 降级** | 书里不写的 bigram（「裁了」「存钱」「生病」）退化成它的两个单字，各打 **0.35** 折扣；已被真词覆盖的字跳过 | 直接丢掉会让查询塌成只剩几个常见词、匹配到全站（「被公司裁了」84 条 vs「被裁」3 条）。**必须跳过已被真词覆盖的字** —— 否则「公司」被算一次 bigram，又被「被公」「司裁」拆成「公」「司」再各算一次，同一条证据计三遍。常见字靠 IDF 自然消失（「了」471 条 → IDF 0.28），**不需要额外的稀有度门槛**（加门槛会把「考」「存」「病」一起误杀） |
| **命中分档** | 标题字面 1.00 > 标题同义词 0.80 > 正文字面 0.45 > 章名 0.35 > 正文同义词 0.22 | 位置比「字面 vs 同义词」更能说明相关度。实测「失眠」三字真出现在一条讲咖啡的正文里，若字面命中给满分，它会压过标题写着「作息固定」的那条 |
| **口语同义词表** | 书里写「经济补偿」，用户说「被裁」；另补外来词/黑话（PUA、offer、内卷、裸辞、优化掉）和错别字（压金→押金） | 书是中文写的，这类词永远不会有正文命中，只能靠表映射 |
| **安全类兜底** | `CRISIS_RE` 匹配整条查询（含口语说法：熬不下去、撑不住、活不下去、一了百了…），命中后**只有「给热线号或让你去门诊」的条目标题**顶格加 3.0 | 加宽的只是「检测」，不是「加分」：`CRISIS_TOP` 只认 `12356 / 12355 / 心理门诊 / 精神科`，**不认「抑郁」二字** —— 否则「心情差就去走或者跑，抗抑郁的效应量」会跟「打 12356」拿到同样的顶格分 |
| **零结果兜底** | 不摆空白页，给出主题最接近的 3 章当出口 | |

### 效果

验收从 30 条扩到 **55 条 + 2 组稳定性**，分基础组/难例组分别设线：

```
                     零结果    首条正确率   平均返回
基础组（30 条短查询）    0/30      78%         22 条
难例组（25 条长句/单字/英文/混排/口语/错别字）
                        1/25      80%         47 条
稳定性（同义改写不该让条数暴涨暴跌）  4 组全部达标
安全类（死 / 想死 / 不想活了 / 活着没意思 / 感觉熬不下去了）
                        5/5 把 12356 那条排在首位
```

对照：同一批用例，旧的整串匹配零结果是 27/30 和 18/22。

### 已知边界（不藏着）

| 做不到 | 例子 | 为什么 / 怎么根治 |
|---|---|---|
| **词中插入打断真词** | 「被公司**裁**了」把真词「被裁」隔开，切不出来，只能退化成单字，于是 36 条（「被裁」只有 3 条） | 字级 bigram 的固有边界。根治要做中文分词（jieba / `Intl.Segmenter`） |
| **否定不做语义反转** | 「不想戒烟」返回的是戒烟的内容 | 没有极性建模。要做得上模型 |
| **纯英文查询** | `unemployment layoff compensation` → 0 条（页面对零结果会走「最接近的 3 章」兜底） | 书是中文写的，没有英文语料。这是语料边界不是 bug |
| **错别字只有手工小表** | 压金→押金 修好了，别的同音字没覆盖 | 要做得上拼音纠错 |
| **需要理解意图的查询** | 「怎么拒绝别人又不得罪人」 | 字面重合度模型做不到，要语义召回 |

### 改搜索的流程

```
改 search.js
  → node test-search.js      # 55 条用例 + 稳定性，退出码 0/1
  → python build.py          # 注入语料 + search.js → index.html
  → python verify.py         # 33 项断言
  → 部署后：node verify-live.js <下载下来的线上 html>
```

**`verify-live.js` 是关键的一步**：它把**线上页面里内联的** `search.js` 和语料抽出来，
用同一套用例跑一遍。验的是真正发出去的那份代码，不是本地副本 —— 避免
「本地测试过了，线上是另一套实现」。同时核对线上语料与 `data/corpus.json` 一致。

`search-test.json` 里的 `expect` 是「正确结果的标题或说人话里应该出现的正则」。
`expect: null` 表示不判首条对错（语料确实没有，或属已知不支持的输入类型）。
`must_not_be_zero` 列出「输入类型必须支持」的查询 —— 语料确实没有的主题
（室友太吵、牙疼）零结果不算失败，但单字、英文、危机措辞必须返回东西。
临界值都写在 `thresholds` 里，**每条都附了为什么是这个数**。

## 几个设计决定

**为什么用 5 维标签而不是问"你是谁"**
每条建议自带 `钱 / 时间 / 毅力 / 收益 / 口径` 五个标签（覆盖率 100%）。这本书是按**性价比**写的，
不是按人群写的 —— 问"你是几年级、什么专业"没有对应的证据支撑，只会制造"它懂我"的错觉。
问资源才是这本书支持得了的问题。

**为什么强调"筛掉多少条"**
`649 条中符合 234 条（筛掉 415 条 —— 它们要花你做不到的东西）`。这个数字是诚实的，
也有用：它回答的是"为什么我做不到那些看起来很好的建议"，而不是"你应该做什么"。

**为什么留着"有争议"标注**
5 条的证据等级带作者批注（`A（争议）`×3、`C（争议）`×1、`B（指南强推荐，但底层证据等级低）`×1）。
解析时**必须把批注单独存下来**，不能只取首字母 —— 那会丢掉作者最重要的判断。
界面上给它们一个独立的橙色徽章，并可以一键排除。

**性价比档照搬作者的算法**
从上游 `index.html` 的 `parseReadme()` 抄来的，保证同一个条目在两边的档位一致：

```js
cs = 钱 + 时间 + 毅力          // 权重 {0:0, 少:0, 多:0}+…
ratio = 收益=大 ? (cs==0 ? '极高' : cs<=2 ? '高' : '一般')
      : 收益=中 ? (cs==0 ? '高' : '一般') : '一般'
```

**注意**：性价比**只在同一口径内可比，与证据等级无关** —— 这是作者本人的说明，页脚也照抄了。

## 路况与坑（实测踩出来的）

| 坑 | 现象 | 解法 |
|---|---|---|
| git **push** 时 TLS 失败 | `schannel: CRYPT_E_NO_REVOCATION_CHECK (0x80092012)` | 见下方「本机 git 配置」 |
| `git clone` 上游 | 同上 | `git -c http.sslVerify=false clone` |
| curl 抓 GitHub | `CRYPT_E_NO_REVOCATION_CHECK` | `curl --ssl-no-revoke` |
| `raw.githubusercontent` 不稳 | 偶发 502、超时 | 优先 `git clone --depth 1`（20 秒 / 6.4 MB） |
| `file://` 下 fetch | CORS 拦截，页面空白 | **语料必须内联**，这是硬要求 |

### 本机 git 配置（这台机器专属，已设好，不用重做）

`C:\Users\Lenovo` 这台机器上直连 `github.com` 的 TLS 会挂在 Windows 证书吊销检查上。
`http.schannelCheckRevoke=false` **无效**，`http.sslBackend openssl` 也验不过直连。
最终可用的是仓库级：

```bash
git config http.sslVerify false     # 仅本仓库
```

这是**安全性降级**（跳过 TLS 证书校验）。换机器或换网络时应该先试
`git config http.sslBackend openssl` + 正确的 CA 证书包；只有在直连确实不通时才退到 `sslVerify false`。

另外本机全局配了 URL 重写，fetch 走代理、push 直连：

```
url.https://gh-proxy.com/https://github.com/.insteadof  https://github.com/
url.https://github.com/.pushinsteadof                   https://github.com/
```

**`gh` CLI 是可用的**（`gh api user` 正常）。网上那种「api.github.com 被劫持、gh 全废」的说法
在本机不成立 —— 那是其他沙箱环境的限制，别照搬。
